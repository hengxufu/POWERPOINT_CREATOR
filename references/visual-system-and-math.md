# 科研PPT视觉系统、字体与LaTeX

当用户指出图案单一、公式排版不规范、字体混乱、缺少艺术字或美观不足时，实际修改代表页并给出前后渲染，不以对象数量作为完成依据。

## 字体

按用户当前要求，原生中文使用微软雅黑（OOXML a:ea 可写 Microsoft YaHei），西文/数字使用 Times New Roman（a:latin/a:cs）。混排段落同时声明两种字体，更新 theme、master、layout 和各页的显式样式，不能只设 python-pptx font.name。数学字体与伸缩符号须按公式引擎验证；校徽、证据图中的像素字和艺术字不受原生字体字段控制，披露这类边界。不要改坏原始证据图来假装统一字体。

`python scripts/typography_check.py deck.pptx --out typography.json` 检查显式声明，并统计Office公式与LaTeX兼容图。它不验证像素字、字体安装或目标Office显示。

## LaTeX公式

每条公式维护 tag、页面、对象ID、LaTeX源、符号含义和来源。优先 LaTeX→MathML→OMML 原生Office公式；实际使用的解析器需支持该命令，不能将未解析命令当作排版成功。

可用本地 TeX Live 的 latex 与 dvipng 编译兼容图，使用 -no-shell-escape/-halt-on-error，并保存 .tex 和编译记录。复杂数学允许Times风格数学包（如newtx）；普通西文正文保持Times New Roman。图像按字体的物理字号与自然尺寸放置，不把每条公式都放大到填满框。

使用 mc:AlternateContent 保存原生公式与TeX兼容表示时，仅处理自己创建的公式节点，不能遍历删除其他AlternateContent；原PPT的表格可能在这类节点中。预览器不支持时生成明确命名的兼容显示版，不能称兼容图本身可编辑。核对公式版与兼容版的公式数量、位置、内容，并披露原生公式是否在实际PowerPoint里检验。

## 图案与艺术字

网页版GPT规划的可复用建议（2026-10-08实测取得，需结合实际材料）：以论述型、技术型、结果型三种页型控制节奏。论述型围绕受证据支持的结论建立图文对照；技术型用原生节点与连接线明确方向；结果型以图表和对比为主体，装饰只在次要边缘。每页保留一个视觉焦点，统一网格、边距、标题层级与线宽。配色继承用户模板；网页建议的颜色只是候选，不覆盖已确认风格。

建立少量互相呼应的视觉语汇：轨道曲线、稀疏点阵、叠层轮廓、节点关系、六边形。依据内容角色分配，不在每页堆满所有图案。统一色相、线宽、留白与光源；章节页允许构图变化，证据页装饰保持次要地位。

艺术字须真实生成、逐字核对、检查alpha并独立插入PPT，保留原生科学标题和语义说明。记录 producer、prompt、原文件哈希、页面与对象名；只有图片哈希实际存在于包内才称已使用。不把任务包准备当成图像生成。用户指定网页版时按其许可使用，替代内置路径需用户明确同意。

简单艺术字优先PowerPoint原生文字填充、渐变和描边，便于直接改字符；复杂生成字标仅作为局部装饰图片，不声称字形可编辑。本轮网页版独立轨道和“融合感知”字标均实际下载、检查、入稿并查看封面渲染。辉光较强的轨道适用于封面局部，不能机械复制到每张结果页。保持原始PNG不裁切不拉伸，用placement的contain框放置；透明边距不代表可随意铺满页面。

先检查封面、章节页、公式页、流程页与最密集表格，再看全篇缩略图；重点核对焦点、阅读次序、字号层级、公式基线、文字溢出、图文比例及装饰是否遮挡证据。不要只加色块和圆角卡片便宣称达到商业模板水准。

[微软LaTeX与OMML支持](https://learn.microsoft.com/en-us/office/math/latex)确认Office数学支持范围；本轮核实2026-10-08。原生Office公式在不同版本的实际显示仍应验证。
