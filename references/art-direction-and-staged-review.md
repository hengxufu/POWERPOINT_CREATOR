# 美术方向与分阶段视觉审查

完整制作、视觉重设计与恢复制作使用；维护任务只用标明合成的离线测试。既有北航身份、40个真实对象、原生编辑性和必要资料交接继续执行。

## 从内容选择美术方向

`art_direction.py`提供三套可调整起点，自动进入GPT规划包和Image共用资料包。它们是设计建议，不是品牌官方VI或审美标准。用户参考与明确要求优先；不要让预设覆盖真实参考。

| design_system.art_direction | 适用叙事 | 构图与美术处理 |
|---|---|---|
| research-editorial | 科研、论文与证据分析 | 白底/浅色主面，主证据占优势；清楚的标题—证据—解释尺度差，概念主体使用细腻哑光与柔光 |
| technical-product | 系统、装置、挑战杯与产品 | 装置主体或原生系统结构为焦点，细节放大与原生编号/接口解释辅助；材质和视角统一，克制使用轮廓光 |
| achievement-story | 国奖、个人成长与经历 | 真实照片、贡献证据和时间节奏；数字层次清楚，强调个人角色，配饰不替代成果 |

优先决定阅读顺序和信息关系，再定图文比例。用尺度差、错落但有基线的非对称构图、稳定留白和少量主辅色产生层次；不要全篇等宽卡片或在每个空角落填装饰。封面/章节可以用更大的主体，结果页让坐标、图例、数据和来源先获得空间。40个独立元素组织成少量语义组，不能拆字或复制无意义配饰补数。

`design_system`声明`color_roles`、`font_roles_pt`和`image_defaults`。统一的默认材质、光照、视角、轮廓、边缘、缩小后细节与光学留白会进入每个素材提示词；继承顺序为全篇→页面visual_context→单素材visual_context，后一层覆盖前一层。需改变同系列风格时给`style_override_reason`说明内容原因。原生排版也使用同一组颜色、字号与间距令牌；不能只统一图片而留下随机字号。

文字在纯色背景可以声明`text_color`/`background_color`。审计给出低对比提醒，4.5是本技能选用的预警起点；照片、渐变、阴影和透明叠层只能通过真实渲染检查。报告不提供“美观得分”，也不证明投影环境可读。

## 自动推进到下一个真实动作

规划接入主文件后，Codex执行：

```powershell
python scripts/auto_workflow.py advance --workspace <workspace>
```

一次执行只做本地可恢复的准备：接入唯一且校验通过的已接收规划、生成内容/几何/美术审计、准备缺失的代表页素材任务。存在多个规划版本时不擅自挑选。资料缺失或几何不合法时，明确返回修复动作。重复执行复用现有任务，保存的job和真实发送记录不被覆盖。

状态器同时识别`asset-jobs`与`assets`下一层版本队列。丢失queue索引时用request_id或slide_id/object_id找回任务；prepared加dispatch-intent也按结果不明处理。存在未知发送意图或重复任务版本时先恢复原会话/确定版本，不重新提交。

同一request有多个已完成/待提交修订版本时，Codex实际比较后执行`auto_workflow.py select-job --workspace <workspace> --request-id <ID> --job <选定任务目录> --reason <具体理由>`。旧任务和证据原地保留；选择绑定当前请求、全篇美术设置与选定规格，变化后需重新判断。其他版本若仍为已提交待查、发送不明或下载阻塞，不能通过选择新版本跳过恢复。此动作只选当前版本，不提交任务。

`advance`不驱动浏览器、不提交消息、不生成图片、不自动批准审查。Codex收到next_action后继续执行实际页面操作、原生组装、渲染与查看，不能停在状态输出。网页登录/CAPTCHA按实际要求处理；普通步骤不重复询问许可。

## 代表页先行

规划使用`representative_slides={cover:slide_id,technical:slide_id,dense:slide_id}`指定封面、关键技术/解释页和密集证据页。未给映射时根据页面类型、布局和证据块推导，并让Codex核对其是否代表本稿。很短的稿件可由同一页承担多个角色，不强制制作三张无关页面。

新工作空间及执行advance的旧空间启用`visual_review_contract`。代表页未实际审查通过时，只自动准备代表页所需的生成任务；其余缺失任务标记等待代表页审查。已有任务与已发送请求照常保留和恢复。完成代表页素材后，先原生组装代表页并渲染。草稿保持全稿页序，尚未制作的页可以预留；不要为取得三张预览先生成全篇素材。

渲染器完成后保存实际索引，例如：

```json
{
  "pptx_sha256":"实际被渲染PPTX的SHA256",
  "slides":[
    {"slide_number":1,"render_file":"renders/slide-01.png","render_sha256":"实际PNG的SHA256"}
  ]
}
```

代表阶段索引覆盖选定代表页，全篇阶段覆盖所有页。路径位于workspace内；哈希必须来自实际文件，不能拿旧渲染配新PPT哈希。索引格式与文件一致只能证明记录对应，不能自动证明渲染器确实渲染了该版本，仍需保留真实渲染过程。

```powershell
# 代表审查通过前创建代表页审查板；通过后同一命令创建全篇审查板。
python scripts/auto_workflow.py advance --workspace <workspace> --pptx <实际草稿或终稿> --renders <实际渲染索引>
# 也可明确选择阶段：
python scripts/visual_review.py --workspace <workspace> --pptx <实际文件> --renders <索引> --phase representative
```

生成`qa/visual-reviews/<版本>/board.html`与`review.json`，保存当时的PPT、规划和渲染副本。审查板直接展示真实页面，便于对照、放大与缩小检查；不能将其图片作为最终PPT整页。首次记录全部pending，任何脚本都不填写通过。

Codex实际逐页查看六项：主焦点、信息层次、对齐与留白、色彩与可读性、素材融合、证据可读性。在review.json中写具体对象、问题和修订；`checks`各项为真实检查结果、`note`为具体观察、`issues`保留未解决事项。只有实际修订并复查完成后才设status=pass、issues=[]。不要求用户逐页重复批准，已有审美偏好明确时由Codex主动执行审查。

代表页通过后再次advance，自动准备其余缺失素材。全篇完成后创建full审查板并逐页实际查看。修改代表页规划或全篇设计规则会使代表审查失效；修改其他单页规划不重置代表审查，但全篇审查必须匹配最终PPT哈希。若直接改了PPT中的代表页样式，也须重新渲染并创建代表审查记录，不能只依赖规划签名。新版本审查单独保存，重复创建相同版本不会抹掉已有观察。

## 修订顺序与交付

先修事实与证据，再修越界/遮挡，再修阅读层次、大小与留白，最后修材质、配饰和艺术字。为单元素调精致度时，先看放大边缘和alpha，再按目标物理尺寸看轮廓，最后在实际页面背景试放。不要用“更高级”作为唯一反馈；说明主体轮廓、边缘、光源、字形或光学大小的具体问题。

`delivery_gate`对启用此合同的空间检查代表页和最终全篇两份审查，保留既有逐页内容/证据记录、图片对象哈希、字体、主题、40元素和编辑性检查。准备好的审查板或几何通过都不是视觉通过。旧任务缺少真实审查时补看当前渲染，不能追填虚构历史。
