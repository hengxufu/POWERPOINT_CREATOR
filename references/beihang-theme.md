# 北航贯穿式视觉主题

本用户要求整份PPT具有高度关联北航的贯穿元素，默认自动启用 `beihang-blue`，不要求每次重述。新工作空间写入主题合同；旧工作空间恢复制作时主动迁移到该主题并重新规划预留区。用户明确指定其他学校或不使用校级主题时，以新要求为准，记录 `theme_profile=none` 及具体用户指令，不把北航标志误植到其他学校。

## 从本地模板学到的规则

来源：`D:\Myself\PPT模板\北航PPT模板` 的12份PPTX。已检查包内颜色、字体、素材及12个内嵌封面缩略图；这不等于已渲染审查所有模板页面。来源哈希与图片原始部件见 `assets/beihang/manifest.json`，分析预览保存在当前项目 `validation/beihang-template-study/`。

- 蓝色工作汇报模板：校徽和中英校名字标、校园建筑全景、蓝白对比。明确颜色包括005BAB、0058E0；另一套包括0C49B7、3889F5。
- 绿园绿模板：校园桥景/绿荫、白色校名、357452与27443D；适合校园人文、成长与实践叙事。
- 银杏黄模板：银杏/校园建筑与9F9C2B、6F7416；适合教学与成长主题，不与蓝色科研全篇混搭。
- 不照搬模板占位字、年份、院系、照片中的人物或成果；模板里的建筑照片只是校园身份素材，不能声称为本课题实验地点或设备。

以上是用户模板观察，不是经核实的学校官方VI规范。默认蓝白科研方案是本项目设计选择，不能称005BAB为已核实的官方标准色。

## 稳定身份层与可变叙事层

每页（包括封面、章节、正文、附录、结尾）保持四个独立对象：真实校徽+中英校名组合图、原生“北京航空航天大学”署名、原生章节文字、原生页码。全篇稳定位置、尺寸、字体与色彩；正文不能遮盖标志，标志不得拉伸、旋转、改字、改色或由AI重画。统一身份≠所有页统一布局。

封面/章节/结尾可增加已打包的校园全景或主楼照片；正文不强制重复大照片。航空航天轨迹、机翼或卫星等研究主题元素可作次级叙事，但通用航天图标不算北航身份证明，不可替代真实校名字标。院系/实验室未确认时只写校名，不猜测沈元学院或其他归属。

默认使用beihang-blue：主色005BAB、辅色0C49B7、白色背景、深灰正文；绿园/银杏分别以357452与9F9C2B作为主色。用户可显式选择beihang-green/beihang-ginkgo，同一篇固定一种。校园图片保持原色；图表用主题色为基底，仍优先保证分类可辨性、色盲可读与数据口径一致。科学配色本身有意义时不得为了统一主题改动含义。

## 自动规划、组装与验证

`auto_workflow.prepare`自动把主题合同和源素材清单写入需求。网页版规划须给出 `design_system.theme_profile`、`recurring_elements`（身份、章节、页码、可选校园元素）、逐页 `section`、`theme_variant`（cover/section/content/closing）与保留区域。身份素材为本地已有源文件，不进入网页版生成任务。可将身份需求描述发给网页，但不自动上传完整模板或素材。

画布相对预留区：右上角为校名组合图（x=.79W,y=.025H,w=.185W,h=.075H）；底部y=.925H以下为署名、章节和页码。主体须避开这些区域。密集公式/结果页仍保留身份，但不得压缩证据字号来迁就装饰。封面等可变校园照片的位置由真实内容规划决定，脚本不盲目插大背景。

生成主内容后、最终渲染前运行：

```powershell
python scripts/beihang_theme.py apply --pptx <build/content.pptx> --plan <planning/deck_plan.json> --profile beihang-blue --out <build/themed.pptx> --report <qa/theme-apply.json>
python scripts/beihang_theme.py audit --pptx <build/themed.pptx> --plan <planning/deck_plan.json> --profile beihang-blue --out <qa/beihang-theme.json>
```

`apply`保留输入，重新应用时只替换`beihang-theme/`保留命名空间内的四个对象，禁止将研究内容命名到该空间。尺寸随画布缩放，校名图保持宽高比；写入原生中文/西文字体。冲突清单只提示人工处理，不移动或删除原内容；有冲突必须改源布局后再组装。Python-pptx重存特殊PPT可能损失不支持部件：复杂原模板/PptxGenJS项目优先在原生成器添加同名同规格四对象，用audit验收，保留原源文件。

`audit`核对实际图片哈希、尺寸比例、可见范围、固定位置、学校署名、章节/页码内容与主题色，逐页不允许缺失。`delivery_gate`对启用主题合同的任务同时检查；模板样式或名称不能当作真实入稿证据。核验不替代渲染：检查封面、技术密集页、结果页及全篇身份一致性、遮挡和留白。报告不自动填写视觉审查pass。

40元素规则独立成立：主题对象按真实可见对象计数，每页这四个对象只计四个；不能复制校徽、拆字或生成无意义装饰填数。剩余差额仍按页面论证规划单元素网页素材。品牌标志与校名永不由图像模型生成。
